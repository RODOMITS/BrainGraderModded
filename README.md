# Brainrot Grader: Python / Bothost

Сохранённый фронтенд подключён к Python-бэкенду Flask + Waitress. SQLite хранит пользователей, виртуальный баланс, инвентарь, историю операций, промокоды и личные версии каталога.

Админка `/admin` доступна всем. Каждый пользователь может редактировать только свою версию каталога кейсов и предметов. Баланс, выдача предметов и прогресс розыгрыша изменяются только у текущего пользователя. Список игроков и чужая история не выдаются через админку; запросы с чужим userId отклоняются сервером. Все пользователи имеют `isAdmin=true`.

Пополнение и вывод отключены: сервер отклоняет запросы к `/api/deposit/*` и все POST-запросы `/api/withdraw*`. Telegram-инвойсы, webhook платежей и трейды Roblox не создаются. Стартовый виртуальный баланс: 10000 BG, тестовый: 100000 BG.

## Развёртывание на Bothost

1. Загрузите ZIP на Bothost или поместите его содержимое в корень Git-репозитория. `main.py`, `requirements.txt`, `Dockerfile`, папка `public` должны лежать в корне приложения.
2. Выберите Python, точка входа `main.py`. При использовании своего Dockerfile включите соответствующую опцию; запуск уже задан как `python main.py`.
3. Включите домен и установите внутренний порт **8000**.
4. Переменные окружения:

   ```text
   PORT=8000
   DATABASE_PATH=/app/data/brainrot.db
   BOT_TOKEN=токен_вашего_бота
   ```

   `BOT_TOKEN` нужен для проверки входа через Telegram. Для посещения в браузере токен не требуется: создаётся отдельная гостевая сессия в cookie. Не помещайте токен в HTML, JavaScript или Git.
5. Запустите приложение. В BotFather настройте кнопку Mini App на `https://ваш-домен/`. Вместе с HTTP-сервером запускается обработчик `/start` через Telegram long polling. Он отправляет приветствие с именем пользователя, кнопку «🎮 Играть» и ниже «📢 Наш Telegram-канал» на https://t.me/brainrotgrader. По умолчанию кнопка игры открывает https://bot-1793525010-3877-rodomits.bothost.tech/. Для другого домена задайте `MINI_APP_URL=https://ваш-домен/` в Bothost. Используется `BOT_TOKEN`; дополнительные библиотеки не нужны. Запускайте одну копию приложения на один токен; существующий webhook у этого бота должен быть отключён для polling.
6. Откройте `/admin`, импортируйте каталог по инструкции ниже и сохраните. Затем вернитесь в приложение. После правок обновите страницу приложения для перечитывания списка кейсов.

Сервер слушает `0.0.0.0`, берёт порт из `PORT`. База создаётся автоматически. В Bothost храните её именно в `/app/data`; каталог `data` исключён из Git и Docker-сборки.

## Оригинальные кейсы и предметы

Оригинальные `/api/cases` и `/api/shop` ответили **401 Unauthorized** при обращении без сессии. В проект уже включён source_catalog.json, полученный из присланного пользователем экспорта оригинального Mini App: 29 кейсов и 154 предметов. Он используется по умолчанию. Во всех кейсах weight=1 у каждой позиции: при N предметах шанс каждого равен 100/N процентов, независимо от цены и редкости. Личные изменения пользователей имеют приоритет над исходным каталогом. Для повторного экспорта:

1. Откройте оригинальный Mini App в Telegram и его DevTools → Console.
2. Откройте файл `export-original.js` из этого проекта, скопируйте его содержимое и выполните в этой консоли. Выполняйте его только на оригинальном сайте `brainrotgrader.com`.
3. Скрипт читает список кейсов, содержимое каждого кейса и доступные предметы магазина. Он копирует JSON каталога в буфер обмена. Данные авторизации остаются в оригинальном приложении и в экспорт не попадают.
4. Откройте свою `/admin`, вставьте JSON в поле каталога и нажмите «Сохранить каталог». Это импортирует данные **только для вашего игрока**.
5. Для общего исходного каталога сохраните этот JSON как **`source_catalog.json` в корне проекта**, рядом с `main.py`, и загрузите проект на Bothost. Все игроки без личных правок увидят этот исходный каталог. Игрок с личными правками продолжит видеть свою копию. Кнопка сброса в админке удаляет только его личную копию.

Оригинальное API не раскрывает вероятности. По запросу пользователя в исходном каталоге установлены равные шансы. При повторном экспорте скрипт ставит `weight: 1` и сообщает об этом в консоли. Это равные относительные веса, а не восстановленные оригинальные шансы. Установите свои веса в админке. Шанс позиции — её вес, делённый на сумму весов кейса. Денежные призы с `coins=true` не импортируются. Правила бесплатных кейсов заменены на одно открытие в сутки без проверки подписки/тега.

Изображения и шрифты запрашиваются с оригинального сайта через перенаправления `/img/*` и `/fonts/*`; логотип и монетка также сохранены локально. Доступность внешних ресурсов зависит от оригинального сайта. В этой среде их загрузка не подтверждена.

## Что реализовано

- Пользователи в Telegram с проверкой подписи `initData`, гостевые пользователи в браузере.
- Личные каталоги, кейсы ×1/×3/×5, ежедневный бесплатный кейс.
- Инвентарь, продажа, магазин, апгрейды, мистери, цветные кубики.
- Тестовый баланс и тестовые открытия; тестовые предметы не участвуют в обычных ставках.
- Общая админка: баланс, выдача предметов, личный JSON-каталог, промокоды на виртуальные BG.
- SQLite-транзакции и повторяемые операции с ключом `key`, без повторного списания при одинаковом запросе.

Рефералы показывают пустые данные; партнёрская программа, серии наград и золотая зона апгрейдов не настроены. Механики и шансы собственной версии не воспроизводят закрытую серверную логику оригинала.


Откройте `http://localhost:8000/`. Настройки Bothost применяются через переменные окружения; `.env` автоматически не загружается.

## Дайс и розыгрыш

Дайс: 0 совпадений — проигрыш; 1 — ×2; 2 и 3 — проигрыш; 4 — ×3. Радужный бонус имеет приоритет и даёт ×10. По умолчанию шанс бонуса 1% на бросок; это правило этой версии, а не восстановленный шанс оригинала. Переменная DICE_BONUS_CHANCE задаёт долю от 0 до 1 (например 0.01). Rig поддерживает также радужный бонус.

Розыгрыш Skibidi Toilet создаётся один раз при первом запуске этой версии и длится 9 дней 4 часа 46 минут. Порог участия — 500 BG; прогресс хранится отдельно от баланса, по умолчанию 0. При отключённых пополнениях он задаётся вручную в админке. Это не платёж и не зачисление баланса. После достижения порога игрок нажимает «Участвовать» и получает номер. По окончании при первом обращении к разделу сервер выбирает победителя и выдаёт предмет в инвентарь ровно один раз. Участники и результаты сохраняются между перезапусками.


## Кастомные предметы

Форма в админке принимает название, цену, редкость и PNG/JPEG/WebP до 1 МБ. Создаётся один экземпляр в инвентаре текущего игрока; тип доступен в магазине, целях и Rig. Метаданные каталога и картинки хранятся в памяти процесса и привязаны к случайному идентификатору в sessionStorage вкладки. Переход между приложением и админкой и обновление страницы сохраняют идентификатор; новая вкладка/сессия получает другой. После перезапуска сервера временные данные исчезают. Неактивная серверная сессия удаляется через 12 часов. Лимит: 20 предметов и 5 МБ изображений на сессию.

Снимки выданных предметов помечены сессией, не показываются в других сессиях и очищаются при перезапуске/истечении срока. Их нельзя передать другому игроку. Кастомные выигрыши исключены из лайв-ленты, топ-дропа и восстановления старых лайв-дропов при запуске. Если каталог кейсов сохраняется вместе с временными предметами, эта версия каталога тоже остаётся только в текущей сессии.


## Моддед и Мины

В настройках появился раздел «Моддед» с отдельными переключателями админки и «Мин». Выключенный раздел не занимает место; его переключатель проявляется при наведении на нижнюю границу настроек (или при фокусе с клавиатуры). Выключенная админка полностью убирается из навигации. Включённые «Мины» появляются после дайса с меткой NEW. Выбор хранится на устройстве; по умолчанию Моддед, админка и Мины включены. Ранее сохранённые выключенные переключатели остаются выключенными до ручного включения.

Мины: поле 5×5, ставка одним обычным или кастомным брейнротом, от 1 до 24 мин. До старта количество мин редактируется. Ставка списывается при начале. Алмаз повышает множитель; бомба сжигает ставку. «Забрать» доступно в любой момент, в том числе до первого хода (×1). Все безопасные клетки автоматически завершают игру. Множитель после k безопасных клеток: 0.99 × C(25,k) / C(25−мины,k), округлённый вниз до двух знаков. До первого хода множитель 1.

При завершении выбирается самый дорогой предмет из личного каталога не дороже выигрыша. Остаток зачисляется на баланс BG. Если подходящего предмета нет — вся сумма зачисляется BG. Игра и открытые клетки хранятся в SQLite, поле не передаётся клиенту до завершения. Один игрок имеет одну активную игру. Обычную игру можно продолжить после перезагрузки. Ставка кастомным предметом действует только в его сессии.

Rig «Мины» позволяет один раз принудительно получить алмаз или бомбу при следующем открытии новой клетки. Он не расходуется на повторный клик по открытой клетке или на завершение игры. Применяется только для текущего игрока. Повтор запросов с тем же ключом не выдаёт награду повторно.


В «Минах» инвентарь использует оформление карточек апгрейдера, включая редкости, метки и выбранную ставку. Рядом доступен тот же магазин: каталог и API покупки общие с апгрейдером, поиск по имени, цены по возрастанию и подтверждение покупки. После покупки предмет автоматически выбирается для следующей ставки. На компьютере инвентарь и магазин стоят рядом, на телефоне переключаются вкладками. Во время активной игры выбор ставки и покупки заблокированы до её завершения.


Поле «Мин», показатели, кнопка и панели инвентаря/магазина имеют общую адаптивную ширину до 720 px. Админка задаёт цвет шапки, фона и нижней панели Telegram как #0c1110. Официальный SDK Telegram сохранён в public/telegram-web-app.js с https://telegram.org/js/telegram-web-app.js (3 ноября 2026), чтобы не ждать сторонний домен при каждом открытии. Скрипты админки загружаются с defer, а начальные данные запрашиваются одним запросом. После обычных действий полный каталог повторно не передаётся. HTML и файлы админки включены в общую версию интерфейса.

### Удобная админка и личная лента
Админка разделена на вкладки: быстрые действия, лайв-дропы, свои предметы, каталог, розыгрыш и промо. Добавлены поиск предметов, текущий баланс и кнопки прибавления сумм к полю баланса (применяются после сохранения).

Во вкладке лайв-дропов выбирается источник: обычные дропы приложения, личный редактор или оригинальный сайт. Редактор сохраняет до 30 записей, позволяет заменять предмет и игру выбранными выше значениями, удалять, перемещать вверх и назначать топ-дроп. Изменения личные, предметы в инвентарь не выдаются.

Оригинальный `/api/home` требует авторизацию Telegram (без неё возвращает 401). Для реальной ленты нужно подключить `Telegram.WebApp.initData` своей сессии оригинала в соответствующем поле. Токен не попадает в SQLite и журнал операций: хранится только в памяти, отдельно для пользователя и вкладки, до одного часа. Запросы идут только на фиксированный адрес оригинала, с таймаутом 4 секунды и кешем 10 секунд. При ошибке показывается её статус, последняя полученная лента сохраняется до истечения подключения. На перезапуске требуется новое подключение. Изменение API или ограничений оригинала может потребовать обновления интеграции.

Rig апгрейдера теперь равномерно выбирает точку внутри выигрышной либо проигрышной зоны вместо её середины. Решение о результате остаётся на сервере.

### Визуальная админка внутри приложения
Админка открывается через `#/admin` внутри общей оболочки с шапкой и балансом. Её документ предварительно загружается после запуска и сохраняется при переходах между разделами; повторное открытие не перезагружает каталог и незавершённые формы. Встроенная версия использует Telegram-авторизацию и SDK родительского приложения, баланс синхронизируется через сообщения с проверкой origin и источника.

Выдача предметов, Rig и редактор ленты используют общий визуальный выбор: карточки с изображением, ценой и редкостью, поиск, фильтр и сортировка. Игры и режимы результата представлены кнопками. Очередь Rig отображает карточки заданных результатов с отдельной отменой.

Каталог по умолчанию показывает карточки предметов и кейсов. Нажатие открывает редактирование; состав кейса меняется через строки предметов с картинками и весами. Импорт и JSON доступны в свёрнутом расширенном разделе. Новый интерфейс использует исходные шрифты, цвета и изображения игры, без отдельной темы.

Дизайн выполнен с применением unslop by Damir Sokolovsky (@heydamir), CC BY 4.0: https://heydamir.design/unslop

Админка использует общий с игрой звуковой движок `ui-audio.js`: в приложении — тот же AudioContext и текущие настройки звука/громкости, при отдельном открытии — тот же движок с настройками из bg_prefs. Звуки проигрываются только после взаимодействия. Добавлены щелчки кнопок и выбора карточек, подтверждение и ошибка, вибрация Telegram; анимации панелей, карточек, диалогов, нажатий и уведомлений учитывают prefers-reduced-motion. Движок игры вынесен из app.js без изменения синтеза звуков.

Rig поддерживает 1–1000 повторов: поле количества и быстрый выбор 1/3/5/10. Повторное добавление полностью совпадающего результата увеличивает остаток, другой результат заменяет его. Карточка показывает остаток. В минах повтор считается за новый открываемый квадрат; в кейсах — за операцию открытия, с заменой первого дропа в ×3/×5. Счётчик уменьшается в транзакции игры, ошибка откатывает расход, повтор запроса с тем же ключом не расходует Rig повторно. Старые настройки без счётчика остаются одноразовыми.

### Серия заходов
Серия включена по умолчанию: один вход за календарный день по Москве, награда доступна до ближайших 00:00 МСК, пропуск дня сбрасывает счётчик. Рекорд хранится отдельно. По умолчанию повторяется семидневный цикл: 100, 150, 200, 250, 300, 400 и 500 BG. Награда выдаётся только по кнопке «Забрать», а не за открытие окна. Серия и получение наград сохраняются в SQLite. Транзакции предотвращают повторную выдачу при параллельных запросах, для получения поддерживается стандартный ключ идемпотентности.

В админке вкладка «Серия заходов»: личное включение, сброс при пропуске, визуальная настройка 1–60 дней цикла, награды BG/брейнрот/случайный предмет из выбранного кейса, изменение своего прогресса. Выбор предмета и кейса — через карточки. Изменения наград относятся к будущим отметкам входа, уже назначенная награда сохраняет свой снимок; если предмет или кейс из конфигурации удалён, будущая награда заменяется на 100 BG. Кастомные сессионные предметы в серию не назначаются. Награды не требуют пополнения, предметы серии не публикуются в лайв-дропах. Ручное изменение прогресса удаляет несобранные награды и не выдаёт наград за прошлые дни; установка 0 начинает новую серию при следующей отметке входа. Проверка входа выполняется при запуске, возвращении в приложение и после смены дня.
